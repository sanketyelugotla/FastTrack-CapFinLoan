SmartSure Insurance Management System
Low-Level Design (LLD) Document
Backend: ASP.NET Core 10 Microservices  |  Frontend: Angular 21
Version 2.0  |  March 2026  |  Complete & Authoritative
1. System Overview
SmartSure is a full-stack insurance management platform composed of four ASP.NET Core 8 microservices behind an Ocelot API Gateway, with an Angular 21 SPA as the client. Each service owns its own SQL Server 2022 database. Asynchronous inter-service communication uses RabbitMQ (via MassTransit). Authentication is JWT HS256 validated independently in every service.

1.2 Cross-Cutting Concerns
Authentication: JWT Bearer (HS256). Token issued by Identity Service; all other services validate using shared Jwt:Key, Jwt:Issuer, Jwt:Audience from appsettings.
Refresh Tokens: Stored in IMemoryCache in the Identity Service with a 24-hour TTL (not persisted to DB).
Logging: Serilog request logging via shared SerilogExtensions enabled in Gateway, Claims Service, and Admin Service.
Error Handling: GlobalExceptionHandlerMiddleware (from SmartSure.Shared.Contracts) maps domain exceptions to standardised HTTP responses.
Environment Config: DotNetEnv loads .env files; services also consume appsettings.json / appsettings.Development.json and environment variables.
Repository Pattern: Policy Service uses explicit repository classes (IPolicyRepository, IInsuranceRepository, IDiscountRepository, IPaymentRepository). Claims and Identity use DbContext directly via services.

4.3 Service Layer
AuthService
Registration: hashes password with BCrypt (via PasswordHasher helper), creates User record, creates Password record, triggers OtpService for email delivery. After OTP verification, publishes UserRegisteredEvent.
Login: validates BCrypt hash, assembles JWT claims (NameIdentifier=UserId, Email, Role), calls TokenService.BuildToken, generates refresh token stored in IMemoryCache with a 24-hour TTL.
Profile: GetProfile/UpdateProfile by UserId from JWT NameIdentifier claim. ChangePassword validates old hash before storing new one.
TokenService (Singleton)
BuildToken: generates HS256 signed JWTs with ClaimTypes.NameIdentifier (UserId), ClaimTypes.Email, ClaimTypes.Role. Expiry configured via appsettings. GenerateRefreshToken returns a cryptographically random opaque string.
OtpService
Generates a random 6-digit OTP, persists an OtpRecord with 10-minute expiry, calls EmailService. Verification checks expiry and Attempts counter (max 5 = lockout). On success, deletes the OtpRecord.
GoogleAuthService
Builds Google OAuth 2.0 authorization URL. On callback: exchanges code for Google ID token, decodes it to extract sub (ProviderKey), email, and name. Upserts User and ExternalLogin records, then issues a SmartSure JWT.
EmailService
Sends SMTP emails (OTP codes, welcome messages, claim notifications). Config from appsettings: SmtpHost, SmtpPort, SmtpUser, SmtpPass.
UserRepository / UserService (Admin Operations)
Repository pattern over IdentityDbContext. UserService provides GetUsers (all, with roles), AssignRole, DeleteUser for admin operations.
MassTransit Consumer
ClaimStatusChangedConsumer: Receives ClaimStatusChangedEvent; sends email notifications to users when their claim status changes (Approved or Rejected).

5.3 IDV and Premium Calculation Logic
The following business rules are implemented in PolicyMgmtService and are central to the quoting and policy creation flows:
Parameter
Rule / Value
Vehicle IDV Formula
IDV = EstimatedValue × (1 − DepreciationRate); minimum ₹10,000
Depreciation ≤6 months
5% (age = 0)
Depreciation 6–12 months
15% (age = 1)
Depreciation 1–2 years
20% (age = 2)
Depreciation 2–3 years
30% (age = 3)
Depreciation 3–4 years
40% (age = 4)
Depreciation 4–5 years
50% (age = 5)
Depreciation >5 years
60% (age > 5)
Home Insurance Value
EstimatedValue × (1 − AgeDepreciation) × PropertyMultiplier; minimum ₹50,000
Age Depreciation
1% per year since YearBuilt; capped at 40%
Property Multiplier
Apartment = 0.90 | House = 1.00 | Villa = 1.10
Premium Formula
Premium = (BasePremium × Duration/12) + (IDV × RiskRate × Duration/12)
Risk Rate – Vehicle
2.5% per year of IDV
Risk Rate – Home
0.15% per year of IDV
Discount Cap
Total discount capped at 30%; MaxDiscountAmount per coupon also respected
First-time Buyer
Automatic 10% discount for users with zero existing policies
5.4 Service Layer
PolicyMgmtService
CalculateQuoteAsync: Looks up subtype and type, determines vehicle/home by type name, calculates IDV, computes premium, returns PolicyQuoteDTO with a human-readable Breakdown string. No database writes.
CreatePolicyAsync: Calculates IDV + premium, calls DiscountService.CalculateDiscountAsync (applies first-time 10% and coupon), creates Policy in Pending status, persists HomeDetail or VehicleDetail as appropriate.
ActivatePolicyAsync: Transitions Pending → Active; publishes PolicyActivatedEvent via RabbitMQ. Guard: if already Active, returns immediately.
CancelPolicyAsync: Delegates to IPolicyRepository.CancelAsync; publishes PolicyCancelledEvent.
GetPolicyDetailsAsync / SavePolicyDetailsAsync: Read/write PolicyDetail records.
GetHomeDetailAsync / GetVehicleDetailAsync: Read asset-specific detail records.
DiscountService
CalculateDiscountAsync: Checks IsFirstTimeOnly eligibility by counting user policies (0 = first-time → 10% auto discount), applies coupon Code match, validates active + not expired, respects MaxDiscountAmount cap, caps total at 30%.
CRUD: GetAll, GetById, Create, Update, Delete discount coupon records.
InsuranceService
Provides CRUD for InsuranceType and InsuranceSubtype entities including seeding/admin management.
PaymentService
Persists Payment records linked to policies. GetPaymentsForPolicyAsync, AddPaymentAsync.
Repositories
IPolicyRepository / PolicyRepository: GetByUserIdAsync, GetAllAsync, GetByIdAsync, AddAsync, UpdateAsync, CancelAsync, GetDetailByPolicyIdAsync, AddOrUpdateDetailAsync, AddOrUpdateHomeDetailAsync, AddOrUpdateVehicleDetailAsync, GetHomeDetailByPolicyIdAsync, GetVehicleDetailByPolicyIdAsync, GetPremiumAmountAsync, SaveChangesAsync.
IInsuranceRepository / InsuranceRepository: GetAllTypesAsync, GetTypeByIdAsync, GetAllSubtypesAsync, GetSubtypeByIdAsync, GetSubtypesByTypeIdAsync, and CRUD operations.
IDiscountRepository / DiscountRepository: GetByCodeAsync used for coupon lookup.
IPaymentRepository / PaymentRepository: GetByPolicyIdAsync, AddAsync.
MassTransit Consumer
UserRegisteredConsumer: Receives UserRegisteredEvent from Identity Service to sync user data context in the Policy database if needed.

8.3 Route Guards
authGuard: Checks if JWT token exists in localStorage. If missing, redirects to /login with returnUrl query param.
userGuard: Checks token exists, then validates role is 'User' or 'Admin' (both allowed). No token → /login. Unknown role → /login.
adminGuard: Checks token, then strictly validates role is 'Admin'. No token → /login. 'User' role → /user/dashboard. Unknown role → /login.
8.4 HTTP Interceptors
authInterceptor (Functional)
Attaches JWT Bearer token to all outgoing HTTP requests. Injects AuthService.getToken(). If a token exists AND the request URL does not contain /auth/login or /auth/register, clones the request and adds Authorization: Bearer {token} header. Login and register requests are explicitly excluded to avoid sending stale tokens.

9. Key Data Flows
9.1 User Registration and OTP Verification
User fills Register form → Angular calls POST /auth/register.
Identity Service: creates User (IsEmailVerified=false), hashes password with BCrypt, stores Password record, generates 6-digit OTP in OtpRecord (10-minute expiry), sends OTP email.
Angular navigates to /verify-otp. User enters OTP code.
Angular calls POST /auth/verify-register-otp with {email, otp}.
Identity Service: validates OTP (checks expiry and attempts count ≤5), sets IsEmailVerified=true, deletes OtpRecord.
Identity Service publishes UserRegisteredEvent via RabbitMQ → consumed by Admin Service (audit log) and Policy Service (user sync).
9.2 Login and JWT Token Flow
Angular calls POST /auth/login with {email, password}.
Identity Service: validates BCrypt hash, assembles JWT claims (NameIdentifier=UserId, Email, Role), signs with HS256, generates refresh token (stored in IMemoryCache, 24-hour TTL).
Response: {token, role, refreshToken}. AuthService stores token and role in localStorage, emits true on authStatus$.
authInterceptor attaches Bearer token to all subsequent requests automatically (excluding login/register).
Guards read role from localStorage to enforce route-level access control.
9.3 Google OAuth Flow
User clicks Google login → Angular calls getGoogleLoginUrl() → redirects browser to /auth/google.
Identity Service builds Google OAuth 2.0 authorization URL and redirects browser to Google.
Google redirects back to /gateway/auth/google/callback (ocelot routes to Identity /auth/google/callback).
GoogleAuthService exchanges code for Google ID token, extracts sub/email/name, upserts User and ExternalLogin records.
Identity Service redirects Angular to /auth/google/callback?token={jwt}.
GoogleCallback component extracts token from URL, stores via AuthService, navigates to dashboard.
9.4 Policy Purchase Flow
User selects InsuranceType and InsuranceSubtype. Enters asset details (vehicle or home).
Angular calls POST /policies/quote → Policy Service returns IDV, premium, and Breakdown string.
User optionally enters coupon code → POST /discounts/calculate returns discounted premium.
User confirms → POST /policies creates Policy in Pending status (discount applied inside CreatePolicyAsync).
Angular calls POST /policies/{policyId}/payments to record payment details.
Angular calls PUT /policies/{policyId}/activate → status transitions to Active. PolicyActivatedEvent published via RabbitMQ.
PolicyActivatedEvent consumed by: Claims Service (stores policy context in Claims DB), Admin Service (writes audit log).
9.5 Claim Lifecycle
User selects a policy and fills claim form → POST /claims creates Claim in Draft status (conflict guard prevents duplicate active claims per policy).
User uploads supporting documents → POST /claims/{claimId}/documents (multipart). DocumentService uploads to Mega.nz, saves ClaimDocument with URL.
User submits → PUT /claims/{claimId}/submit transitions Draft → Submitted. StatusHistory written. ClaimSubmittedEvent + ClaimStatusChangedEvent published.
Admin views claim in admin dashboard (GET /admin/claims). Admin sets to UnderReview via PUT /admin/claims/{claimId}/review (audit log written via AuditService).
Admin approves: PUT /admin/claims/{claimId}/approve → Admin Service proxies to Claims Service. Status → Approved. ClaimStatusChangedEvent published.
OR Admin rejects: PUT /admin/claims/{claimId}/reject → Status → Rejected. ClaimStatusChangedEvent published.
ClaimStatusChangedEvent consumed by Identity Service → sends email notification to the user.

12. Security Considerations
Password Storage: Passwords are hashed using BCrypt (via PasswordHasher helper) and stored in a separate Password table, isolated from the User entity to prevent accidental hash exposure.
JWT Validation: Each service independently validates JWT tokens using a shared signing key. The API Gateway does NOT validate tokens — this is by design (Ocelot passthrough).
Refresh Token Storage: Refresh tokens are stored in IMemoryCache (in-process, not distributed). This means they are lost on Identity Service restart. No DB persistence is used for refresh tokens in the current implementation.
OTP Security: OTPs are 6-digit numeric strings with a 10-minute expiry. A max of 5 verification attempts is enforced before lockout (OtpRecord.Attempts counter). OtpRecord is deleted on successful verification.
CORS: Restricted to specific origins in the gateway. Credentials are allowed only for those origins.
Authorization: All sensitive endpoints use [Authorize] attribute. Admin-only endpoints use [Authorize(Roles = "Admin")]. Route guards provide an additional client-side layer.
File Upload: Documents are uploaded to Mega.nz (third-party encrypted storage). Only the returned URL is stored in ClaimDocument.FileUrl. Content-Type and FileSize are validated on upload.
Google OAuth: ProviderKey (Google sub ID) is stored in ExternalLogin to uniquely identify OAuth users. No password is stored for Google-auth users (IsGoogleAuth=true).
